# V2 测试与验收计划

## 固定行为测试

将 `cases.json` 的 12 个问题作为独立对话运行。测试行为，不锁定具体措辞。

每个答案必须先通过默认层检查：

- 10 秒内能指出首选与下一步。
- 只有一个首选；备选只由明确条件触发。
- 结论最多一句，行动不超过 3 步，风险或变更条件不超过 1 条。
- 默认层不出现固定免责声明、完整来源表或与行动无关的背景。
- 事实旁使用带文字的证据状态，完整元数据按需展开。
- 缺少非关键条件时先声明假设并给结果，不用追问阻塞用户。

再检查场景不变量：硬条件先过滤；官方与经验分离；不预测资格或结果；不虚构实时信息和截止日期。

## 形式选择测试

检查答案是否根据任务结构选择形式，而不是一律输出卡片：

| 结构 | 应选形式 |
| --- | --- |
| 单一事实或一步操作 | 短答 |
| 至少 3 个方案 | 突出首选的排序表或路径 |
| 条件决定适用性 | 条件流程 |
| 至少 4 个时间节点 | 时间轴 |
| 至少 5 个任务或需要勾选 | 解锁面板 |

页面成为主答案时，对话只给首选、一个动作和文件入口，不重复全文。

## HTML 验收

四个样例分别在 1440 × 1000、390 × 844 和 320 × 700 检查：

- 首屏出现一个明确首选和一个立即动作。
- 地点、资源、制度、规划四页的结构明显不同。
- 筛选、勾选、条件分支、复制或日历导出按页面目标工作。
- 页面无横向溢出，Tab 可到达核心控制，触控目标约 44px。
- JavaScript 关闭后，首选、动作和证据仍可阅读。
- 状态同时有符号与文字；颜色不是唯一编码。
- `prefers-reduced-motion` 下没有多余动画。
- 无远程脚本、样式、字体、统计或浏览器存储。
- 只用简短“演示数据”说明样例边界。

## 实时检查

运行 `scripts/check_live_sources.py`，记录核心官方入口可访问性。入口暂时异常不等于包结构失败，但行为测试必须验证 Skill 会明确降级，不能伪装已核验。

## 通过标准

- 包结构与 Skill Creator 验证均通过。
- 12 个案例的默认层规则和场景不变量全部满足。
- 4 个 HTML 样例通过桌面、窄屏、键盘、无脚本与交互检查。
- ZIP 根目录直接包含 `SKILL.md`，且内容与仓库一致。
