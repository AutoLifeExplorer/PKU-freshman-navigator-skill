# 测试与验收计划

## 固定测试

`cases.json` 保存 12 个行为测试，不锁定措辞，只检查：

- 是否路由到正确场景。
- 是否在需要时联网，或在联网失败时正确降级。
- 是否只追问一个会改变结论的关键问题。
- 是否区分官方规则与经验信息。
- 是否禁止结果预测、虚假实时信息和未核实日期。
- 是否选择合适的输出形态，并为桌面端保留完整纯文本。

运行 Skill 行为测试时，将每个 `prompt` 作为独立新对话输入，人工或评测器根据 `invariants` 判定。不要用正则匹配固定句子代替行为判断。

## 实时测试

实时测试用于发现外部状态变化：

1. 运行 `scripts/check_live_sources.py`，检查核心官方入口可访问性。
2. 在当前学年独立执行前三个核心提问。
3. 确认答案展示学年、检索时间、官方来源和经验来源分组。
4. 抽查所有关键链接是否直达原始页面，而非搜索结果页。
5. 若当年页面尚未发布，确认 Skill 明确说未知并给出关注入口。

网站临时不可用不等于 Skill 结构失败；但 Skill 必须显示降级状态，不能伪装已核验。

## 网页验收

对三个 HTML 样例分别检查：

- 1440px 与 390px 宽度无横向溢出、遮挡或不可读区域。
- Tab 键可到达筛选、链接、勾选、证据抽屉和导出按钮。
- JavaScript 关闭后核心内容仍存在。
- `prefers-reduced-motion` 下没有必要动画。
- 没有外部脚本、样式、字体、统计或跟踪请求。
- 页面显著标注“非北京大学官方产品”和样例数据边界。

## 通过标准

- 包结构验证无错误。
- 12 个固定测试的关键不变量全部满足。
- 核心官方入口实时检查没有永久失效；临时异常有记录。
- 三个网页样例桌面与窄屏视觉检查通过。
- ZIP 根目录直接包含 `SKILL.md`。
