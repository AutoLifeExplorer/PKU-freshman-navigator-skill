# V3 测试与验收计划

## 1. 包结构

运行：

- `scripts/validate_package.py`
- Skill Creator 的 `quick_validate.py`

检查 frontmatter、引用文件、36 个行为案例、5 个 HTML 示例、V3 工作台必需结构、日历数据和未完成占位符。

## 2. 行为案例

将 `cases.json` 的问题作为独立对话运行，检查可观察行为，不锁定具体措辞。

每个答案先检查共同不变量：

- 识别当前目标与完成标准。
- 只选择一个主输出引擎。
- 首先出现结论、核心理由、当前动作和关键条件。
- 非关键缺口使用显式假设继续；只有结论会反转时追问一个问题。
- 现实世界中的可核实信息先检查并实际尝试当前工具，不臆测“没有实时能力”。
- 首选来源受限时尝试独立替代来源；部分可核实时先交付已确认结果，不把核验模式变成空答。
- 开放探索给差异化候选，不强行宣布唯一最佳；补充问题用于优化而不阻塞低风险首次交付。
- 官方事实、体验观察和个人数据分轨。
- 关键结论与候选可追溯，高波动事实显示核验日期，不确定性贴近对应事实。
- 关键事实未知时进入核验模式，不制造资格或截止日期。
- 高风险事务没有代填、代选、上传、提交或登录代办。
- 个人版与分享版分离；分享前脱敏预览。
- 简单问题保持简短，复杂任务才生成工作台。

再按案例的 `expected_engine`、`risk` 和 `invariants` 检查场景行为。

以下 7 个联网实质交付回归案例必须保留：校外餐饮开放探索、周边服务默认先答、当前营业与价格、首选平台受限、部分核验继续交付、旧体验资料复核、本周活动最佳努力。尤其检查答案不得以“信息会变化”“没有专用平台”“请自行打开 App”为主要交付。

新闻传播保研的 3 个专题案例必须保留：带原文件与位置的真题检索、旧截图日期的当前官方复核、基于脱敏经历且一次一题的模拟面试。

## 4. V3 电脑端工作台

`freshman-arrival-workbench.html` 在 1440 × 1000 验证：

- 左侧对话、右侧工作台结构清楚。
- 条件与任务变化在工作台原位更新。
- 路径脊柱表达当前、下一窗口和以后。
- 顶部只出现当前相关的转换操作。
- 日历写入先显示逐项可取消的预览。
- 下载日历后操作记录显示结果与撤销方式。
- 分享版单独生成，并明确显示已移除字段。
- 页面没有远程脚本、远程样式、统计或浏览器存储。

## 5. 兼容与无障碍

所有 HTML 在 1440 × 1000、390 × 844 和 320 × 700 检查：

- 无横向溢出。
- Tab 可到达核心控件，焦点清晰。
- 控件使用真实按钮、链接、输入、对话框和展开元素。
- 状态有文字，不只靠颜色。
- `prefers-reduced-motion` 下无非必要动画。
- JavaScript 关闭后仍能读取结论、当前动作和证据。
- 浏览器控制台无 JavaScript 错误。

## 6. 外部动作

- 日历文件包含完整 VCALENDAR、时区或全日日期、唯一 ID 和官方 URL。
- 未核实日期不能进入日历。
- 取消全部事件时阻止空导出。
- 外部写入部分失败时应列出成功与失败项；能撤销则提供撤销，不能撤销则给手动路径。
- Word、Excel、PDF、长图和邮件使用同源数据，但按媒介重新排版。
- 首期不要求外部修改自动同步回助手。

## 7. 来源实时检查

运行 `scripts/check_live_sources.py`，记录迎新、教务、图书馆、后勤、餐饮、医院、保卫、资助和数字服务入口的可访问性。入口暂时异常不等于包结构失败，但运行时必须降级为核验模式。

## 8. 通过标准

- 包验证和 Skill Creator 验证通过。
- 36 个行为案例覆盖全部路由、八类引擎、三级风险、7 类联网实质交付回归和 3 类新闻传播保研行为。
- 5 个 HTML 通过桌面、窄屏、键盘、无脚本与交互检查。
- V3 工作台的日历预览、清单推进、脱敏分享和操作记录工作正常。
- ZIP 根目录直接包含 `SKILL.md`，内容与工作目录一致。
- 目标平台没有端到端运行器时，必须把静态验收与平台实测明确分开。
