# V3 输出体系设计稿

> 状态：已确认，作为 V3 实施基线  
> 设计对象：北京大学大一校园助手  
> 默认终端：电脑端  
> 时间范围：收到录取通知后至大一暑假结束  
> 本文只定义产品与交互体系，不直接修改现有 Skill、输出契约、示例或测试。

## 1. 设计结论

V3 不以“支持更多格式”为目标，而把输出升级为一个可操作的校园任务系统：助手理解意图，选择一种主输出，在电脑端工作台中帮助用户完成判断；用户确认后，再把结果转换为日历、地图、文档、表格、邮件或分享内容。

核心公式是：

`一个任务对象 → 一个主工作台 → 若干按需转换 → 用户确认后的低风险联动`

成功不是页面更丰富，而是用户更快得到明确下一步、理解判断依据，并以更少的手工操作完成任务。

## 2. 产品原则

### 2.1 任务完成优先

- 默认层必须回答“现在最应该做什么”。
- 一个回答只设一个主输出；其他形式是转换、导出或联动。
- 视觉、动画和媒体只有在降低理解或行动成本时才出现。
- 高风险场景的正确终点可能是“完成核验”，而不是“执行事务”。

### 2.2 自动选择，允许转换

助手根据任务结构自动选择主输出，不让用户先学习格式菜单。工作台顶部只显示与当前任务相关的转换，例如“加入日历”“打开地图”“导出 Word”。用户也可以通过“换种方式”主动切换。

### 2.3 准备好，确认后执行

- 助手可以生成预览、检查冲突和准备低风险写入。
- 用户可以逐项取消或编辑，再进行一次明确确认。
- 外部动作进入操作记录；支持部分重试，并尽可能支持撤销。
- 高风险事务不代办，不操作官方业务界面字段。

### 2.4 同源数据，媒介适配

工作台、PDF、长图、Word、Excel、日历和邮件共享同一个任务对象，但根据媒介重新排版。外部格式不复刻工作台，也不重新猜测事实。

### 2.5 结构确定，表达可生成

- 日期、地点、资格、来源、状态和用户选择使用结构化字段。
- 流程、地图、课表、时间轴和清单由固定组件渲染。
- 模型负责理解意图、解释理由、生成草稿和调整语气。
- 插画、音频和视频从已核验的文字底稿衍生。

## 3. 用户与覆盖范围

### 3.1 主用户

主用户是学生本人。用户可以主动分享脱敏结果给家长、同学或群聊，但产品不提供家长监控入口，也不允许接收者查看学生的位置、成绩、健康信息或私人任务进度。

### 3.2 生命周期主导航

主导航按大一生命周期组织：

`录取后 → 报到前 → 报到当天 → 开学前两周 → 第一学期 → 寒假 → 第二学期 → 大一暑假`

事务领域作为搜索和筛选维度。首页展示当前阶段、最重要的一件事、下一个观察窗口和已订阅提醒，而不是展示功能大全。

### 3.3 内容覆盖

1. 入学与报到：材料、行李、账号、缴费、体检、住宿、路线和开学初任务。
2. 学业与选课：培养方案、课程、课表、考试、学籍、学习空间和学术资源。
3. 校园空间与出行：地点筛选、地图、路线、无障碍条件和交通衔接。
4. 日常生活：食堂、宿舍设施、维修、快递、打印、购物、网络和公共设备。
5. 校务办理：证明、预约、报销、材料、部门分流和咨询草稿。
6. 经济支持与权益：奖助、贷款、勤工助学、费用、免费资源和申诉入口。
7. 健康、安全与紧急支持：校医院、医保、心理支持、安全分流和紧急入口。
8. 校园参与：社团、讲座、比赛、志愿活动、报名、组队和分享。
9. 个人成长：阶段目标、科研、竞赛、交流、实习和长期规划。
10. 数字工具：门户、教学平台、邮箱、VPN、数据库和软件资源。

### 3.4 明确不做

- 不替用户完成考试、作业或学术不端行为。
- 不进行医疗诊断、法律裁定或结果保证。
- 不预测奖学金、排名、推免、录取或名额结果。
- 不代办选退课、申请、缴费、医疗、身份材料等高风险事务。
- 不索取密码、验证码，也不绕过统一身份认证。
- 不把论坛传言、群聊截图或营销内容当作官方事实。
- 不把与校园生活无明显关系的通用百科和消费导购扩写为核心能力。

## 4. 任务对象：所有输出的共同底座

每次任务先形成一个内部任务对象，再选择输出引擎。建议字段如下：

| 字段组 | 核心字段 | 用途 |
| --- | --- | --- |
| 意图 | `goal`、`task_type`、`completion_definition` | 定义用户要完成什么以及完成标准 |
| 身份 | `lifecycle_stage`、`department`、`campus` | 判断适用范围和当前阶段 |
| 条件 | `hard_constraints`、`preferences`、`assumptions` | 区分硬条件、偏好与显式假设 |
| 方案 | `options`、`primary_choice`、`alternatives` | 支持决策与条件备选 |
| 行动 | `next_action`、`tasks`、`dependencies` | 生成流程、清单和进度 |
| 时间 | `time_window`、`verified_dates`、`reminders` | 生成时间轴和日历 |
| 空间 | `origin`、`destinations`、`route_constraints` | 生成地图与路线 |
| 证据 | `claims`、`sources`、`scope`、`verified_at` | 支持核验、冲突与引用 |
| 权限 | `data_permissions`、`external_actions`、`risk_level` | 控制门户读取和外部联动 |
| 呈现 | `primary_engine`、`allowed_conversions`、`language` | 选择工作台和导出方式 |

### 4.1 完成状态

任务状态统一为：

`需要补充条件 → 可以判断 → 等待用户确认 → 已生成结果 → 外部操作中 → 已完成 / 部分完成 / 需要核验`

状态名称面向用户表达，不在界面暴露内部术语。

### 4.2 风险等级

| 等级 | 示例 | 助手权限 |
| --- | --- | --- |
| 低风险 | 创建日历、导出文件、生成分享图 | 预览并确认后执行 |
| 中风险 | 材料检查、申请草稿、咨询邮件 | 生成与检查；用户自行使用 |
| 高风险 | 选退课、奖助申请、缴费、医疗、身份材料 | 只解释、模拟、检查和提供入口；不操作官方字段 |

### 4.3 状态保存边界

工作台默认是当前任务的临时操作面。筛选条件、模拟结果和未确认草稿不自动进入长期记录。只有用户明确选择“保存计划”“订阅提醒”或完成低风险外部导出后，才保留相应派生结果与操作记录；需要长期协作或跨软件维护的状态仍由日历、文档、表格和待办工具承接。

## 5. 输出选择规则

输出引擎由任务结构触发，而不是由校园领域固定绑定。

| 任务结构 | 主输出引擎 | 典型信号 |
| --- | --- | --- |
| 只需知道或立即做一步 | 行动简报 | 单一事实、单一动作 |
| 需要在多个方案中选择 | 决策面板 | 比较、推荐、匹配、取舍 |
| 需要到达或理解空间关系 | 地图与路线 | 去哪里、附近、怎么走 |
| 资格或步骤存在条件分支 | 流程向导 | 是否适用、怎么办、缺什么 |
| 结果受日期、顺序或冲突影响 | 时间工作台 | 截止、课表、日程、阶段 |
| 需要完成多项并跟踪状态 | 清单与进度板 | 准备、收集、逐项完成 |
| 需要提交、整理或沟通 | 可编辑成果 | 文档、表格、邮件、消息 |
| 需要传播、随行或辅助理解 | 传播与辅助媒体 | 分享、打印、讲给我听 |

当一个任务同时具有多种结构时，按用户当前完成目标决定主引擎，其他结构成为内嵌区块或转换项。不得同时并列多个等权主输出。

示例：“帮我安排报到当天并发给家长”以时间工作台为主，内嵌路线摘要；完成后再转换为脱敏长图，而不是同时生成时间轴、地图、卡片墙和一篇长文。

## 6. 八类输出引擎

### 6.1 行动简报

**适用**：单一事实、当前动作、状态确认、紧急分流。  
**首屏**：结论、核心理由、一个主行动、必要条件。  
**交互**：展开证据、修改关键假设、继续询问。  
**转换**：复制、邮件草稿、加入清单。  
**约束**：不为了统一视觉而强行生成网页卡片。

### 6.2 决策面板

**适用**：地点、课程、活动、资源与方案比较。  
**首屏**：当前首选或分类匹配结果、淘汰原因、改变结论的条件。
**交互**：切换硬条件与偏好；结果即时重排；查看理由。  
**转换**：路线、课表、日历、对比表、分享卡。  
**约束**：硬条件和偏好足以排序时可给唯一首选；开放探索先给有差异的候选，不为满足模板制造“最佳”。兴趣、价值观和重大人生选择只给匹配空间与试走路径。

### 6.3 地图与路线

**适用**：找地点、比较空间成本、报到动线与无障碍路线。  
**首屏**：目的地、核心路线、预计核验项、到达后指引。  
**交互**：更换起点、路线偏好和目的地；打开外部地图。  
**转换**：路线卡、报到行程、打印地图、分享地点。  
**权限**：实时位置按次授权，只用于当前路线，不进入长期档案。  
**约束**：地图或实时数据不可用时，不虚构距离、拥挤或营业状态。

### 6.4 流程向导

**适用**：制度、资格、办理、材料和部门分流。  
**首屏**：是否适用、判断依据、当前动作、改变结论的条件。  
**交互**：回答少量条件问题；查看使用了哪些个人字段；展开规则节点。  
**转换**：材料清单、咨询邮件、PDF、官方入口。  
**约束**：证据充分时可以给个性化判断；缺少关键事实时自动进入核验模式。高风险流程不提供代填或代办控件。

### 6.5 时间工作台

**适用**：课表、日程、阶段规划、截止日期、时间冲突。  
**首屏**：现在、下一窗口、关键冲突、一个立即动作。  
**交互**：日/周/月/阶段切换；拖动只用于模拟；调整提醒；查看依赖。  
**转换**：`.ics`、课表图、清单、PDF。  
**约束**：只有官方确认的精确日期可写成正式日历事件；模糊窗口保留在时间轴。

### 6.6 清单与进度板

**适用**：报到、材料准备、资源开通和阶段任务。  
**首屏**：当前最重要任务、完成标准、被阻塞事项。  
**交互**：勾选、标记不适用、调整顺序、查看依赖。  
**转换**：日历、Excel、PDF、外部待办副本。  
**约束**：使用功能性完成度，不加入积分、排行榜或强制连续打卡。

### 6.7 可编辑成果

**适用**：Word、Excel、表单草稿、邮件、微信消息和正式材料整理。  
**首屏**：成品预览、仍需用户补充的字段、事实与措辞检查。  
**交互**：直接编辑、切换语气、查看差异、选择导出格式。  
**转换**：`.docx`、`.xlsx`、`.pdf`、复制、邮件草稿。  
**约束**：首期只做单向导出；外部修改通过用户主动导入和差异确认回流。

### 6.8 传播与辅助媒体

**适用**：群聊分享、家长说明、随行查看、音频导览和操作教学。  
**首屏**：传播对象、脱敏结果、有效时间和来源入口。  
**交互**：切换受众、预览脱敏字段、选择画幅或语言。  
**转换**：长图、单页图片、二维码卡、音频、视频摘要。  
**约束**：音频与视频按需生成，并始终保留可核验文字底稿；个人版不能直接作为分享版。

## 7. 电脑端工作台

### 7.1 核心布局

电脑端采用“对话 + 工作台”双栏结构。对话负责表达意图、补充条件和解释变化；工作台负责比较、操作、编辑与导出。

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 当前阶段：开学前两周       全局搜索                    个人与来源状态 │
├──────────────────────┬───────────────────────────────────────────────┤
│ 对话                 │ 任务标题               [转换] [导出] [更多] │
│                      │                                               │
│ 用户目标             │ ┌ 路径脊柱 ─ 当前动作 ─ 下一窗口 ─ 以后 ┐   │
│ 助手解释             │ │                                           │   │
│ 关键追问             │ │        当前主输出工作区                   │   │
│ 变化摘要             │ │  决策 / 地图 / 流程 / 时间 / 清单 / 文档 │   │
│                      │ │                                           │   │
│ [继续问助手]         │ └───────────────────────────────────────────┘   │
│                      │ 证据与假设   操作记录   外部联动预览           │
└──────────────────────┴───────────────────────────────────────────────┘
```

建议初始比例为对话区 32%、工作台 68%，允许用户折叠对话区。工作台不在每次对话后重复创建新卡片；条件变化在原位更新，并由对话区用一句话说明“什么变了、为什么变”。

### 7.2 顶部操作栏

- 主操作最多展示 3–4 个，使用可预期的动词命名。
- 只显示当前任务可用的转换，不提供固定的格式大全。
- “更多”容纳低频导出、语言转换、版本和反馈。
- 高风险工作台不出现“替我办理”“自动填写”或相似暗示。

### 7.3 桌面与移动分工

- 电脑端：培养方案、课表冲突、复杂比较、材料整理和多窗格操作。
- 手机端：查看当前动作、提醒、导航、勾选和分享。
- 两端使用同一任务对象；移动端不是独立维护的简化答案。
- 仍需支持 320px 无横向滚动，但设计优先级以电脑工作台为准。

## 8. 视觉方向：燕园路径签 V3

### 8.1 设计命题

主题仍是“在陌生校园里迅速找到下一步”，但从单页导视扩展为桌面任务工作台。视觉重点不是校园纪念品式装饰，而是把一条真实的任务路径贯穿不同输出引擎。

### 8.2 色彩令牌

| 名称 | 色值 | 语义 |
| --- | --- | --- |
| 石青灰 | `#DCE6E3` | 环境底色、非当前区域 |
| 纸白 | `#F7F8F5` | 主工作面 |
| 墨色 | `#17231F` | 正文与主要结构 |
| 导视红 | `#7C2435` | 唯一主行动、当前节点 |
| 银杏黄 | `#D9A928` | 时间窗口、即将到来 |
| 湖蓝 | `#2D6274` | 来源、核验和次级状态 |

不得新增无语义的大面积渐变。错误、成功等系统状态可在组件层增加通过对比度测试的辅助色，但不得改变上述核心语义。

### 8.3 字体角色

- 标题与阶段名称：系统宋体回退，营造校园文书与路牌的文化质感。
- 正文与控件：系统中文黑体回退，保证长时间桌面操作的清晰度。
- 时间、状态、版本和数据：系统等宽字体回退，帮助扫描精确字段。
- 不加载远程字体，不用书法字体承担正文或操作标签。

### 8.4 标志性元素：路径脊柱

工作台使用一条“路径脊柱”编码真实任务结构：它可以在条件分支处分叉，在等待核验处中断，在当前动作处使用导视红，在时间窗口处转为银杏黄，在证据节点处连接湖蓝来源标记。

这是 V3 唯一允许明显强化的视觉表达。其他区域保持纸面般安静，避免卡片墙、装饰性编号、漂浮渐变和无意义图标。

### 8.5 风险自适应

- 日常探索与分享：可以使用插画、校园氛围和轻量动效。
- 学业与正式办理：降低装饰，突出字段、差异和来源。
- 健康、安全与紧急场景：移除非必要动画与品牌叙事，只保留分流和行动。
- `prefers-reduced-motion` 下关闭路径绘制等动画；唯一信息不得依赖悬停或运动。

## 9. 信息可信度与核验模式

### 9.1 三条信息轨道

| 轨道 | 内容 | 展示要求 |
| --- | --- | --- |
| 官方事实 | 资格、日期、费用、规则、入口、开放要求 | 发布者、适用范围、发布时间、核验时间 |
| 体验与观察 | 拥挤、噪声、插座、口味、工作量、校外消费体验 | 来源类型、观察时间、可信度，不伪装为保证 |
| 个人数据 | 课表、偏好、任务状态、当前位置 | 显示用途与权限，不进入公开分享版 |

官方来源、历史背景和学生经验继续遵循现有来源策略。来源冲突时比较适用对象、时间和文件性质；仍无法解决时并列显示并给核验入口。

### 9.2 执行模式与核验模式

当关键事实完整且已核验时，工作台进入执行模式，可以生成低风险行动预览。当资格、日期、开放状态或适用范围缺少关键依据时，工作台自动进入核验模式：

- 主按钮改为“查看官方说明”“联系负责部门”或“补充条件”。
- 未确认日期不得写成正式日历截止日。
- 未确认资格不得显示为“你符合”。
- 往年规则只作背景，不补全当前结论。

核验模式仍需保留已确认结果。低风险地点、消费和活动任务不得退化为只有“自行查看地图／官网”的空状态；来源受限时显示已确认候选、核验日期与逐项缺口。

### 9.3 导出快照

PDF、长图、日历和文档等可能过期的输出必须包含：生成时间、适用对象、核验状态和返回最新工作台的入口。导出物是快照，不承诺自动更新，也不静默修改用户已有日历。

### 9.4 验证发布源

- 学校职能部门和院系可以作为官方发布源接入核验系统。
- 学生组织可以提供活动信息，但必须显示主办方、适用对象与有效期。
- 商家和非校方机构不进入官方可信层，但可作为校外生活服务的商业线索或体验来源；商业内容必须显著标识，营销材料不能单独支撑体验排名。
- 发布内容先结构化为候选事实，再由来源策略判断与用户当前任务的相关性。
- 任何发布源都不能直接写入用户计划、订阅或日历；仍需用户确认。

### 9.5 用户纠错

用户可以在工作台对事实、入口、地点体验或交互问题一键反馈。反馈可以立即影响该用户的当前筛选，但不能未经审核升级为公共事实。

- 官方规则类纠错必须重新核验官方原始来源。
- 地点体验类反馈记录观察时间、来源类型和可信度。
- 默认不附带用户身份、完整课表或精确轨迹。
- 审核后的修正进入来源或体验轨道，并保留版本与核验时间。

## 10. 权限、隐私与分享

### 10.1 门户授权

校园门户登录可以作为核心能力基础。助手通过统一身份认证读取完成当前任务所必需的数据，不接触密码和验证码。

- 每次读取说明用途和字段范围。
- 一次授权不扩展为读取全部成绩、资助、医疗或身份信息。
- 门户原始数据只在当前任务中短暂使用。
- 用户明确保存的课程计划、提醒、偏好和任务状态可以长期保留。
- 再次需要精确信息时重新从门户读取。

### 10.2 轻量校园档案

可由用户主动保存：年级、院系、校区、宿舍片区、出行方式、自习偏好、饮食限制、提醒主题和常用软件。成绩、排名、经济状况、医疗心理信息、身份号码、精确轨迹和私人聊天默认不进入长期档案。

用户可以查看“本次结果使用了哪些信息”，并随时修改、导出或删除档案。

### 10.3 分享隔离

- 分享必须从个人版重新生成脱敏版。
- 用户先选择受众并查看脱敏预览。
- 分享版保留来源、适用范围和生成时间。
- 个人课表、起点、私人备注、资助状态和健康选择默认移除。
- 家长、同学和群聊接收者只能获得用户主动分享的内容或副本。

## 11. 外部联动

### 11.1 首期范围

| 渠道 | 首期能力 | 边界 |
| --- | --- | --- |
| 北大统一门户 | 最小授权读取课表、培养方案、个人办理状态 | 高风险业务只提供入口，不操作字段 |
| 系统日历 | 生成 `.ics` 和导入预览 | 仅精确、已核验日期；检测重复 |
| 高德/百度/Apple 地图 | 打开地点与路线 | 实时能力交给地图；不保存轨迹 |
| Office/WPS | 导出 `.docx`、`.xlsx`、`.pdf` | 根据媒介重新排版 |
| 微信 | 长图、文字、二维码和复制 | 不直接代发；分享前脱敏 |
| 邮件 | 主题、正文和附件清单草稿 | 用户检查并自行发送 |

待办软件首期使用通用清单、表格或可复制格式，不为每个品牌开发双向连接。

### 11.2 操作预览与记录

外部写入前展示：将创建什么、哪些项目被取消、提醒设置、未核实字段和可能重复项。用户一次确认后执行已选低风险项目。

操作记录显示：成功、失败、部分完成、外部标识、可撤销范围和重试入口。无法自动撤销时，提供定位和手动删除路径。

### 11.3 同步边界

首期是单向导出。用户在 Word、Excel、日历或外部待办中的修改不会自动同步回助手。需要回流时，由用户主动导入，系统展示差异，用户选择合并项。

多人协作也交给外部工具。助手可以生成共享副本、候选时间或协作文档，但不自建多人实时编辑、权限冲突和版本历史。

## 12. 五条首期用户旅程

### 12.1 报到准备

**跨度**：录取后至开学前两周。  
**主路径**：时间工作台 → 清单与进度板 → 地图与路线 → 日历/文档/分享。  
**完成标准**：用户知道当前最重要任务，材料和账号前置条件已明确，已核实日期进入日历，报到当天路线可用，并顺利切换到开学初任务。  
**关键边界**：不把尚未发布的安排制造为截止日；门户账号未开通时明确前置条件。

### 12.2 选课与课表

**主路径**：决策面板 → 时间工作台 → 课表图/日历。  
**数据**：官方课程要求、个人培养方案、已修课程、时间冲突与可追溯体验。  
**完成标准**：用户理解选择与取舍，得到无冲突的模拟课表和个人核验清单。  
**关键边界**：不做“水课榜”、不保证成绩、不替用户操作选课系统。

### 12.3 校园地点选择

**主路径**：决策面板 → 地图与路线 → 分享地点卡。  
**条件**：开放与准入、时间、距离、无障碍要求、插座、声音、消费条件和体验可信度。  
**完成标准**：明确决策时得到满足硬条件的首选、条件备选和可打开的路线；开放探索时得到可追溯、可继续筛选的分类候选。
**关键边界**：实时位置按次授权；官方状态和体验属性分开。

### 12.4 制度与办事流程

**主路径**：流程向导 → 材料清单 → 咨询草稿/官方入口。  
**完成标准**：用户知道规则是否适用、使用了哪些个人条件、还缺什么、下一步去哪核验。  
**关键边界**：证据完整时可以明确判断；不确定时进入核验模式；高风险业务不代填、不代办。

### 12.5 大一阶段规划

**主路径**：四年路线背景 → 默认滚动四周时间工作台 → 清单与进度板。  
**完成标准**：用户只看到当前重点、未来四周行动和下一个观察窗口，同时能展开长期依赖。  
**关键边界**：不把所有事项标成紧急，不预测排名、奖项或录取结果。

## 13. 提醒与主动性

助手默认响应用户请求。只有用户按主题明确订阅后，才持续提醒时间窗口或规则变化。

- 精确日期默认通过用户选择的日历承载。
- 模糊窗口保留在助手阶段看板，不制造截止日。
- 助手内提醒与日历是默认渠道。
- 邮件等其他渠道逐项授权。
- 微信用于主动分享，不作为默认提醒渠道。

## 14. 语言、媒体与人格

- 简体中文是默认语言；可一键转为英文或中英对照。
- 制度翻译保留官方中文术语，英文明确为辅助理解。
- 语言人格保持熟悉校园、认真替新生判断的学长学姐感。
- 不把持续出现的虚拟头像或数字人作为核心界面。
- 低风险欢迎、导览和阶段回顾可以使用轻量角色插画。
- 音频适用于行走、通勤和无障碍；视频限于少数复杂操作教学。

## 15. 无障碍与失败状态

### 15.1 无障碍基线

- 完整键盘操作与清晰焦点。
- 使用语义化标题、按钮、链接、输入和展开控件。
- 状态同时使用文字，不只依赖颜色、图标、动效或空间位置。
- 支持放大、高对比度、减少动画和屏幕阅读器。
- 图表提供文字等价内容；音视频提供字幕或文字稿。
- 重要操作不设置过短超时。

### 15.2 失败状态

失败信息必须说明发生了什么、影响了哪些项目以及下一步怎么做。不得只显示“操作失败”。

- 门户未登录：说明需要登录以及登录后将读取哪些字段。
- 门户或来源不可用：先尝试适用的独立替代来源；仍不可用时保留已知内容，标记上次核验时间并进入核验模式。
- 外部写入部分失败：列出成功与失败项，允许只重试失败项。
- 空结果：解释哪个硬条件淘汰了全部方案，并允许修改该条件。
- 无网络：V3 不承诺核心功能离线；可显示已有快照，但必须标明可能过期。

## 16. 衡量与验收

### 16.1 核心指标

1. 目标任务完成率。
2. 从提问到形成明确下一步所需时间。
3. 为完成任务发生的反复追问和软件切换次数。
4. 导出或联动后的手工修改量。
5. 用户能否复述结论依据、假设和不确定性。
6. 关键事实错误、过期和误导比例。
7. 高风险事务边界的正确拦截率。

视觉满意度、分享率和页面停留时间只作为辅助指标。

### 16.2 组件验收基线

每个输出引擎至少验证：

- 1440px 桌面双栏工作台。
- 390px 与 320px 窄屏视图。
- 键盘、屏幕阅读器语义和减少动画。
- JavaScript 失效时仍能阅读结论、当前动作和证据。
- 执行模式与核验模式切换。
- 导出物的时间戳、适用范围和脱敏。
- 外部操作预览、部分失败与撤销说明。

## 17. V2 → V3 迁移方案

V3 是产品范围与交互架构升级，不应一次覆盖掉当前可工作的 V2。后续实施建议按以下顺序进行。

### 17.1 第一阶段：建立共同模型

- 新增任务对象、风险等级、信息轨道和输出选择规则。
- 将当前地点、资源、制度、规划四类结构映射到八类引擎。
- 保留现有来源政策、证据账本和纠错流程。

### 17.2 第二阶段：重写输出契约

- 将“文本或自包含 HTML”扩展为“工作台主输出 + 媒介转换”。
- 将网页自动触发阈值改为任务结构判断，数量阈值仅作辅助信号。
- 增加操作预览、权限、分享脱敏、导出快照和核验模式契约。

### 17.3 第三阶段：建立电脑端外壳

- 先实现双栏工作台、路径脊柱、统一操作栏、证据抽屉和操作记录。
- 再逐个实现八类引擎；优先支持五条首期旅程所需组件。
- 保留移动端适配，但从 V2 的移动首屏优先调整为桌面工作台优先。

### 17.4 第四阶段：接入门户与外部格式

- 先验证统一身份认证、字段授权和只读数据可用性。
- 优先落地 `.ics`、地图深链、`.docx`、`.xlsx`、`.pdf`、长图和邮件草稿。
- 所有外部动作先实现预览和操作记录，再开放实际写入。

### 17.5 第五阶段：更新测试与示例

- 在原有 26 个范围、旅程与风险案例上，增加 7 个联网实质交付回归案例，共 33 个。
- 后续新闻传播保研扩展再增加 3 个专题案例，当前总数为 36 个。
- 将 `offline-place` 从“必须离线回答”改为“断网时展示快照与核验状态”。
- 将 `desktop-fallback` 改为验证桌面工作台降级与文本等价内容。
- 新增门户最小授权、高风险禁止操作、分享脱敏、重复日历、部分失败和导入差异测试。
- 现有四个 HTML 示例在对应 V3 引擎样例通过评审后再替换。

## 18. 实施前需要验证的事实

以下不是待定产品决策，而是进入实现前需要通过官方或技术环境确认的事实：

1. 北大统一身份认证允许接入的方式、字段、会话边界和授权要求。
2. 课表、培养方案和办理状态是否存在可合法读取的结构化接口。
3. 高德、百度与 Apple 地图在目标环境中的深链和坐标兼容性。
4. Office/WPS 对生成文件、链接和二维码的兼容性。
5. 微信环境对长图、二维码、复制内容和链接打开方式的限制。
6. 桌面端宿主对文件生成、下载、外部打开和撤销记录的能力。

事实验证失败时，应替换对应实现方式，不改变本文已经确认的权限与风险边界。

## 19. 设计评审检查表

- 是否只有一个主输出，并能说明为什么选它？
- 首屏是否出现结论、核心理由、当前动作和关键条件？
- 用户能否在结果内修改高频条件，而不必回到聊天反复描述？
- 转换入口是否只显示当前有意义的选项？
- 是否复用了结构化数据，而不是为每种媒介重新生成事实？
- 是否区分官方事实、体验观察和个人数据？
- 关键事实未知时，是否进入核验模式？
- 高风险场景是否完全没有代填、代选、代交控件？
- 外部动作是否有可编辑预览、明确确认和操作记录？
- 分享是否重新生成脱敏版？
- 视觉结构是否表达真实任务关系，而不是卡片装饰？
- 是否满足电脑端效率、窄屏降级和基础无障碍？
- 是否能用任务完成与可靠性指标验收？
