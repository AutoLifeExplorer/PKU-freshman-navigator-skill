# 来源与实时检索策略

只在处理规则、资源、日期、开放状态或入口时读取本文件。

## 1. 先确定检索范围

将北京时间映射到北大当期校历，并显式记录本次使用学年。用户已说明入学年份、年级或历史时间时，以用户信息为准。不要用“2026 届”和“2026 级”互相替代：前者通常指毕业年份，后者通常指入学年份。

检索至少包含：主题、适用学年、北京大学、负责部门或用户院系。优先搜索原始页面和原始附件，不以搜索摘要代替页面正文。

## 2. 来源分层

### A 级：制度结论可直接采用

- `pku.edu.cn` 及其明确归属学校职能部门、院系的子域名页面。
- 北京大学教务部、学生工作部、信息公开网、图书馆、计算中心、招生部门等官方原始页面或附件。
- 用户所属院系官网发布的当年细则。
- 经页面身份、账号主体和原始发布时间核实的北京大学官方微信公众号原文。

### B 级：只作官方背景或入口线索

- 往年官方通知、往年学生手册、历史页面。
- 官方新闻稿、年度报告或介绍页，但它们未必代表当前可用状态。
- 校内门户、预约系统或登录页的公开说明。不要尝试索取用户密码或绕过权限。

### C 级：只作经验信息

- 可识别作者或学生组织、带时间的学生公开分享。
- 地图平台的营业状态、评论与路线估算。
- 媒体转载的校园经验；尽量追溯原始发布者。

### 禁止用于制度结论

- 群聊截图、匿名论坛、搜索摘要、营销软文、无日期二手整理。
- 模型记忆或经验库中未附可核验来源的断言。

## 3. 冲突处理

1. 先比较适用对象：院系细则可细化该院系规则，但不能被外院规则替代。
2. 再比较适用时间：同层级采用发布时间更晚、明确适用于本学年者。
3. 再比较文件性质：正式办法或通知优先于新闻稿、问答和宣传稿。
4. 仍有冲突时，不自行裁决；并列说明冲突、建议联系的部门与官方入口。

## 4. 最低核验动作

### 制度与长期规划

- 至少核对一份当年中央或职能部门来源。
- 涉及院系差异时，再核对用户院系来源；用户未给院系且差异会改变答案时，先追问院系。
- 检查发布日期、适用年级、附件版本与页面是否仍可访问。

### 免费资源

- 核对当前用户范围、费用、激活入口、网络条件和失效条件。
- 不因历史页面列出某软件就断言当前仍授权；优先当前服务页或平台页面。

### 地点

- 开放状态、预约要求和服务时间查官方页面。
- 路线与营业状态需要地图或当前页面；没有实时工具就标“待核验”。
- 插座、噪声和拥挤度属于经验属性，不能伪装为官方保证。

## 5. 证据账本字段

对每个会影响行动的结论记录：

- `claim`：准备告诉用户的具体结论。
- `source_class`：A / B / C。
- `publisher`、`title`、`url`。
- `published_at`、`applicable_year`、`retrieved_at`。
- `scope`：全校、院系、专业、年级或具体地点。
- `status`：confirmed / background_only / experience / unresolved。
- `conflict_note`：若有冲突，写清差异。

## 6. 搜不到或联网失败

不要填空式猜测。采用以下结构：

1. 已能确认什么。
2. 哪一项尚未找到当年官方依据。
3. 往年官方信息仅作背景（若确实有帮助）。
4. 用户应联系或关注的部门与入口。
5. 可立即做且不依赖未知规则的行动。
